Task 11 · Complete Mobile App Experience

CareSlot

A mobile clinic-booking app that lets users find a suitable healthcare provider, choose an available appointment time and leave with a confirmed booking.

Core product promise: Find a clinic → choose a service → select a time → confirm the appointment. The prototype is one connected experience, not a collection of unrelated screens.

1. App idea

Problem: finding an appropriate clinic and confirming availability can involve calls, uncertainty and repeated back-and-forth.

Main user goal: book a clinic appointment at a convenient time and receive a clear confirmation.

2. Core user journey

Welcome→Authentication→Home→Find clinic→Details→Select slot→Patient form→Success

3. Information architecture

HomeUpcoming appointment · quick booking · nearby clinics · specialties
FindSearch · clinic results · details · available slots
AppointmentsUpcoming · past · appointment status
ProfilePersonal details · notifications · privacy · support

Navigation

Persistent bottom navigation provides four destinations: Home, Find, Appointments and Profile. The booking process becomes a focused task flow so users can complete the main action without distraction.

4. Main screens

01 · WelcomeValue proposition + Get started
02 · AuthenticationSign in / create account
03 · HomeUpcoming booking + discovery
04 · FindSearch + clinic results
05 · DetailsClinic information + slots
06 · BookingPatient information + payment method
07 · ConfirmationAppointment ticket + next actions
08 · AppointmentsConfirmed/past bookings

5. Important states

  • Loading: checks nearby providers and availability.
  • Empty: no search results or no past appointments.
  • Error/recovery: search can be cleared or retried rather than trapping the user.
  • Unavailable: booked appointment slots are visibly disabled.
  • Disabled: Continue stays unavailable until a slot is selected.
  • Success: confirmation presents clinic, service, date, time and status.

Consistent 8px spacing rhythm, 12–18px rounded components, high-contrast typography, restrained green action colour and repeated card/button patterns create a coherent product language.

Design rationale

Each screen answers the user's next question: What do I need? → Where can I go? → When can I go? → What do you need from me? → Is it booked?
